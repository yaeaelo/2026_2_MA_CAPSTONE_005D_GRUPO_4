### Abstract

BeatsCloud es un marketplace académico de instrumentales que reúne publicación de pistas por productores, descubrimiento y previsualización para artistas, y un flujo de compra con acceso protegido. El corte técnico corresponde a `felipe-urtubia/BeatsCloud`, rama `main`, commit `f017627fec99b2628e7753d3626ed33367836c5c`. La solución integra una SPA React/TypeScript/Vite, backend Django con API JSON propia, PostgreSQL, sesiones con CSRF, Webpay Plus y almacenamiento local con una integración opcional de Cloudflare R2. En ese corte se documentan 372 pruebas Django y 26 frontend, TypeScript/lint, build y comprobaciones HTTP locales. Estas verificaciones no son una ejecución manual E2E ni prueban servicios externos reales. La evidencia académica identifica el código fuente mediante `SOURCE_COMMIT.txt` y `SHA256SUMS`.

## 1. Proyecto, problema y oportunidad

El problema abordado es la fragmentación entre publicar instrumentales, descubrir productores/pistas, previsualizar audio y controlar el acceso a archivos comprados. BeatsCloud propone reunir esas operaciones en una plataforma web para productores y artistas. Esta formulación describe la necesidad funcional que motivó el producto; los documentos disponibles no contienen entrevistas, estudio de mercado ni validación cuantitativa de usuarios, por lo que no se presenta como una necesidad comercial demostrada.

La oportunidad de producto es probar un flujo integrado de catálogo musical, perfiles, metadatos, carrito, pago y acceso autorizado. La [visión de producto](https://github.com/felipe-urtubia/BeatsCloud/blob/f017627fec99b2628e7753d3626ed33367836c5c/docs/entrega-apt/vision_producto.md) la califica como hipótesis no aprobada por cliente/Product Owner y advierte que no existe análisis comparativo de mercado.

## 3. Solución, arquitectura y desarrollo

- **Frontend:** React 19, TypeScript, Vite 6 y Tailwind CSS en `frontend/client/`.
- **Backend:** Django 6 y API JSON propia en vistas Django; no utiliza Django REST Framework ni JWT en el SHA de corte.
- **Datos:** PostgreSQL mediante modelos y migraciones Django.
- **Autenticación:** sesiones Django y protección CSRF.
- **Audio y archivos:** previews generadas con FFmpeg; streaming/descarga de originales sujetos a permisos de propietario o compra. Almacenamiento local y flujo opcional Cloudflare R2.
- **Pagos:** Webpay Plus/Transbank. Los tests con mocks/dobles validan ramas de código, no transacciones reales.

La integración permite que Vite sirva el cliente y reenvíe `/api` y `/media` al backend local. La documentación técnica del producto incluye [arquitectura y endpoints](https://github.com/felipe-urtubia/BeatsCloud/blob/f017627fec99b2628e7753d3626ed33367836c5c/docs/entrega-apt/arquitectura.md), [modelo y almacenamiento](https://github.com/felipe-urtubia/BeatsCloud/blob/f017627fec99b2628e7753d3626ed33367836c5c/docs/entrega-apt/modelo_datos_y_almacenamiento.md) y [guía reproducible](../Evidencias%20Proyecto/Evidencias%20de%20sistema/BeatsCloud-f017627/README.md).
