## 1. Proyecto, problema y oportunidad

El problema abordado es la fragmentación entre publicar instrumentales, descubrir productores/pistas, previsualizar audio y controlar el acceso a archivos comprados. BeatsCloud propone reunir esas operaciones en una plataforma web para productores y artistas. Esta formulación describe la necesidad funcional que motivó el producto; los documentos disponibles no contienen entrevistas, estudio de mercado ni validación cuantitativa de usuarios, por lo que no se presenta como una necesidad comercial demostrada.

La oportunidad de producto es probar un flujo integrado de catálogo musical, perfiles, metadatos, carrito, pago y acceso autorizado. La [visión de producto](https://github.com/felipe-urtubia/BeatsCloud/blob/96918f43f147d46d5ae65746c988979c36854637/docs/entrega-apt/vision_producto.md) la califica como hipótesis no aprobada por cliente/Product Owner y advierte que no existe análisis comparativo de mercado.

## 3. Solución, arquitectura y desarrollo

- **Frontend:** React 19, TypeScript, Vite 6 y Tailwind CSS en `frontend/client/`.
- **Backend:** Django 6 y API JSON propia en vistas Django; no utiliza Django REST Framework ni JWT en el SHA de corte.
- **Datos:** PostgreSQL mediante modelos y migraciones Django.
- **Autenticación:** sesiones Django y protección CSRF.
- **Audio y archivos:** previews generadas con FFmpeg; streaming/descarga de originales sujetos a permisos de propietario o compra. Almacenamiento local y flujo opcional Cloudflare R2.
- **Pagos:** Webpay Plus/Transbank. Los tests con mocks/dobles validan ramas de código, no transacciones reales.

El commit `5021ee8` añadió preparación para Render: proxy HTTPS, `STATIC_ROOT`, WhiteNoise, Gunicorn y `build.sh`. En el cierre, `bash build.sh` se ejecutó en entorno QA aislado: collectstatic terminó y no hubo migraciones pendientes. No se creó ni probó un servicio Render, no se conectó PostgreSQL alojado ni se ejecutó Gunicorn externo. Como el script aplica migraciones durante build, su uso en un proveedor debe configurarse deliberadamente.

La integración permite que Vite sirva el cliente y reenvíe `/api` y `/media` al backend local. La documentación técnica incluida en el snapshot verificable describe [arquitectura y endpoints](https://github.com/felipe-urtubia/BeatsCloud/blob/96918f43f147d46d5ae65746c988979c36854637/docs/entrega-apt/arquitectura.md), [modelo y almacenamiento](https://github.com/felipe-urtubia/BeatsCloud/blob/96918f43f147d46d5ae65746c988979c36854637/docs/entrega-apt/modelo_datos_y_almacenamiento.md) y [guía reproducible](../Evidencias%20Proyecto/Evidencias%20de%20sistema/BeatsCloud-96918f4/README.md).
